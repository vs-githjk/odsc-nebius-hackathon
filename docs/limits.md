# Where Patient Zero is wrong

This page lists every way we know Patient Zero can give a wrong or weaker answer: what goes wrong, an example you can run, the rule that should catch it, whether it is caught today, and who owns the fix. Nothing here is softened. If you find a failure that isn't listed, please open an issue.

Every open row that names a test is pinned in [packages/pz/test/limits.test.ts](../packages/pz/test/limits.test.ts) as the engine behaves **today**. Those tests pass while the gap is open. When a gap is closed, its test fails on purpose, and the PR that closes it has to flip the test and update the row here, so this page can't drift from the code.

## The biggest one first

**No recorded trace ends on its origin yet.** Across the live E2 runs on Nov 17 and 18 ([eval/dev-score.md](../eval/dev-score.md), recordings in [eval/dev-traces/](../eval/dev-traces/)), the latest row (run 3 plus 2 re-records) gives false origins 0 and cold stops 8 of 9, but target cited 3 of 10 and the earliest page right on 1. Patient Zero stops honestly when it can't back an origin; what it can't yet do well is reach and date the origin. Most misses never reach the origin page (target cited 3 of 10). Where it is reached, dating is the cause: a page's first archive capture dates its URL, not the sentence on it, so a listing or a later-edited page can rank earlier than the report it quotes (dev-10, dev-17; Rohan's archive-date fix, [#3](https://github.com/vs-githjk/odsc-nebius-hackathon/issues/3)). The first run's causes and fixes are on [#192](https://github.com/vs-githjk/odsc-nebius-hackathon/issues/192). The rows below come from tests, planted cases and these runs. The SAMPLE traces in [fixtures/traces/](../fixtures/traces/) are invented, and the app and `make replay` (its default trace) label them SAMPLE.

| L16 | **A trail can stop before it reaches the origin, at a cap.** The walk stops stepping back after `caps.depth` 8 steps back in time (F7, [#203](https://github.com/vs-githjk/odsc-nebius-hackathon/pull/203): a step is a round whose search window moved earlier), and starts no new round once `caps.ms` (300 s) has passed. | L18 | **A page that presents the claim as already said is never the origin, but only for the wordings on the list.** "the seemingly ubiquitous admonition to drink at least eight 8-oz glasses" ends the page's chance to be the origin ([#225](https://github.com/vs-githjk/odsc-nebius-hackathon/pull/225), dev-04 on the third live run, PubMed 12376390). The cues are `rules.json` `priorUseCues`: an admonition or adage, "commonly said", "the popular belief", "you've probably heard", "it is often said". Other wordings still pass: "you may have read that", "many people think", "a claim doing the rounds". So does a listed cue in the sentence before the span: only the span's own text is read, never the text around it. The other way, a cue on any earliest page, in any of its spans, ends the trail cold, even when another earliest page is the real origin. | test L18; [packages/pz/rules/rules.json](../packages/pz/rules/rules.json) `priorUseCues` | The typed `same_claim` question, which does not ask whether a page repeats the claim or makes it. | **Partly**. Only the listed wordings. | Anoop with XO (#225) |
| L19 | **A first archive capture dates the page only if it holds the claim's sentence, but only for pages we can read.** The archive's first capture dates the URL, not the sentence: dev-10's biologicaldiversity.org ocean-plastics page was dated 2013-06-13 though that copy never held "outweigh all the fish in the sea by 2050", and dev-17's Microsoft listing page was dated 2019 for a 2023 sentence. Now the capture is fetched (the archive's own `id_` copy), its text is reduced to lower-case words, and the date stands only if one of the node's spans appears in it, whole words, in order, next to each other. If it does not, or the capture cannot be read (404, timeout, rate limit), the page gets no date from it: its own metadata or byline if it has one, else unconfirmed with no value, with the first capture kept for display. It still misses: a capture that holds the sentence but is not where the sentence began (the same words quoted or syndicated on an earlier page we never found); a sentence the page reworded in the capture so the words differ (the date is withheld, which costs a true date, never gives a false one); files we cannot read, and a file replaced on the server after its only archived capture (the one-digest fallback cannot see it). A PDF is read with a small text reader of our own (it inflates the streams and reads the strings the pages show; it misses fonts that code their glyphs through a table, and ligatures such as "fi" come out as control codes, so for a PDF the codes and the letter pairs fi, fl and ff are dropped on both sides before comparing), and the same word-for-word test applies; a PDF that lacks the sentence is withheld, however many versions the archive holds. This is how dev-10's WEF report keeps its 2016-01-20 date: the archive holds two versions of that file, so a "never changed" rule would have dropped the true origin, but its first capture does hold the sentence. A match needs a span of at least six words, and a place right after a negation prefix ("it is a myth that") does not count. Only a file the reader cannot read at all (an image, a PDF whose fonts hide the text, a response over 25 MB, a PDF that inflates past the safety caps) falls back to the archive's own record: the first-capture date stands if the archive holds one distinct version of the file (one digest), assumed, not proven, to be the file the walk read. A redirect to another capture counts as unreadable. A file that changed and could not be searched is left unconfirmed, even if its first version held the sentence. Only the first capture is tried; no later capture is probed. Traces recorded before this rule keep their stored dates. | test L19; [packages/pz/src/engine/capture.ts](../packages/pz/src/engine/capture.ts) `captureHoldsClaim` | Nothing else. Metadata and byline dates are unchanged and make no capture request. | **Partly**. Text pages whose sentence is in the first capture; files with one archived version. | XO (archive-date fix) |

## Measured so far, and not yet

These sections get filled from real runs, misses included, in the PR that commits each run.

- **Top causes from the first live dev run (T54, #112):** from XO's replay of the 17 recordings ([#192](https://github.com/vs-githjk/odsc-nebius-hackathon/issues/192)). (1) A page where `same_claim` said a confident "no" can still become the earliest page, and the next searches then end before the true origin: 8 claims (dev-02, 04, 06, 09, 10, 11, 18, 20). (2) Pages that got a `same_claim` yes were dated years late, because a DOI page was not sent to Crossref and in-page dates were read after Wayback: dev-09, dev-11, dev-14. (3) The only false origin, dev-13: its earliest page names an earlier print source in words ("In the November/December 2009 issue of World Watch"), and code counts only links as an earlier citation. Fixes are on #192, each with a replay re-score.
- **Gallery misses (T92, #159):** the answers were committed before any trace ([#168](https://github.com/vs-githjk/odsc-nebius-hackathon/pull/168)). The traces aren't run yet. Every MISS and PARTIAL goes here.
- **Rematch losses (T93, #160):** the protocol and the draw are in [#171](https://github.com/vs-githjk/odsc-nebius-hackathon/pull/171), but nothing has been run or graded. Every claim where a rival did better goes here.
- **Held-out misses (T67, #125):** the held-out run isn't done. Every miss goes here, as it is.
