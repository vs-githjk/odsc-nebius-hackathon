## 4. Jev and the typed decision layer

**What Jev is (FOUND, VERIFIED in Vidyut's own code and notes).** TypeSafe AI's "System One" decision model, `jev`. You send a `state` plus typed questions and get typed answers back, never prose: yes/no as one probability (`noul`), choice with per-option probabilities and a confidence, or a score on an ordered rubric. Vidyut built a client for it in YinZone: `~/HouseHack/packages/api/src/system-one/types.ts` (question and answer types), `client.ts` (Zod-validated responses, named error codes `not_configured`, `http_error`, `network_error`, `bad_response`, "a failed request is never turned into a decision here"), `no-client-exposure.test.ts` (key never reaches the browser), and `packages/api/src/typology/site-fit.ts` (`REVIEW_CONFIDENCE = 0.3`: below it a rating is shown but flagged "needs review"; the score uses the probability-weighted expected value, not the raw top pick, so an even split does not become a confident extreme). Model id there: `typesafe/jev-1.13-20260917` via OpenRouter. It was also planned as a shadow judge in PrismAI (`~/.claude/projects/-Users-vidyutsriram-Agentic-Meeting-Copilot/memory/project_oct12_state.md`: `POST https://api.typesafe.ai/v1/systemone`, `jev-latest`, kept off). Portfolio note: `~/Portfolio-notes/facts-yinzone-betterbill.md` lines 38 to 41 ("Jev ratings not validated against ground truth"). Status conflict: the coordinator's sources say early access since Sep 15 2026 (REPORTED); a PrismAI memory note of Oct 5 calls it GA (REPORTED). Not checked on the web.

**Where Patient Zero's decisions already have Jev's shape.**

| PZ decision | Shape | Who decides today (brief) | Typed version |
|---|---|---|---|
| Is this page a meta or debunk page? | yes/no | code keyword rule | code rule first; typed yes/no only when no keyword fires but the page mentions the claim near "myth"-like context |
| Is this page a copy of that one (cluster or not)? | yes/no | embeddings plus byline and overlap rules | rules first; typed yes/no only for pairs in the embedding grey zone |
| Did the wording change on this hop? | choice of 8 labels (faithful, number changed, unit changed, hedge dropped, scope widened, comparison added, attribution shifted, context stripped) | code atom diff, then Qwen with an enum schema and `logprobs` | the main use: choice with per-option probabilities |
| How much stronger is the child claim? | score (same / somewhat stronger / much stronger) | not modelled | optional, expected-value score as in `site-fit.ts` |
| What kind of page is this? | choice (study, dataset, official report, speaker's own words, news, blog, social, other) | implied by ORIGIN FOUND's "primary document" | typed choice; ORIGIN FOUND needs a primary type above threshold |

**Recommended design (primary path stays on Token Factory).**
1. **One schema file** (`decisions` in Zod if the team picks TypeScript, Pydantic if Python) defines each question: id, type, options, instructions, review threshold. The same definitions produce (a) the Token Factory `json_schema` request, (b) the typed answer stored in the trace JSON, (c) the UI types, with a CI drift check as in mvr M6.
2. **Token Factory call per question:** `Qwen/Qwen3-30B-A3B-Instruct-2507` with `json_schema` constrained to the option ids (one short id per option, so the first generated token is the choice) and `logprobs` with top alternatives. Code turns the option-token logprobs into per-option probabilities and a confidence; it never reads free text.
3. **Below threshold, the answer is "unsure", never a verdict.** An unsure hop is drawn neutral, not red, and shows its top two options with probabilities ("number changed 52%, faithful 41%"). Code's atom diff still wins on contradiction ("disputed", as planned). This is the rubric's "acknowledge uncertainty rather than inventing".
4. **Calibration table on the dev set** (the LifeOS idea): for hop labels, bucket by confidence and report how often the label matched the hand label. Pick the threshold from the dev set, freeze it, then run held-out once.
5. **Jev itself: at most an optional ablation row** ("hop labels: Qwen typed vs Jev typed, agreement and calibration on the dev set"), and only if access is free and quick; it needs an OpenRouter or TypeSafe key and spend, so Vidyut's OK first, and it never runs in the shipped path.

Rubric: Agent design +1 (explains how decisions are made and when it is unsure), Works +0.5 (one contract across four builders), Sourced: protects. Hours: about 3 net (schema plus generator 1.5, logprob probabilities 1, calibration table 0.5). Maturity: **Experimental** as a whole. Typed structured output and shared schemas are Proven; logprob confidence from an enum choice is Emerging (calibration varies by model, and whether Token Factory returns logprobs together with `json_schema` is UNVERIFIED: add one line to the week-0 smoke calls); Jev is Experimental (weeks old, "not validated against ground truth" in Vidyut's own use).
